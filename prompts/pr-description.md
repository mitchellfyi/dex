# PR Description Template

## PR Title Format

```
<type>(<scope>): <short description>
```

If the project uses ticket IDs in PR titles, include them:
```
<TICKET-ID>: <type>(<scope>): <short description>
```

**Types**: `feat`, `fix`, `refactor`, `perf`, `docs`, `test`, `chore`, `build`, `ci`, `style`, `revert`

Examples:
- `feat(database): add KPIs table with demand analytics`
- `fix(inventory): resolve race condition in batch allocation`
- `refactor(api): extract payment validation into reusable service`
- `PROJ-123: feat(auth): add OAuth2 login flow` (with ticket ID)

## Attribution Rules

- Before finalizing a PR title or body, invoke the `humanizer` skill. Preserve
  template headings, checkboxes, code blocks, commands, paths, ticket links,
  metrics, and the required footer exactly.
- Include `Generated by Dex` as the final footer when the project has no stricter PR template.
- Do not include Claude attribution in any form, including `Generated with Claude Code`, `Generated by Claude`, `Authored with Claude`, or Claude co-author trailers.
- If a project-specific PR template has its own required footer, preserve that template and still remove any Claude attribution text.

## Checklist

- [ ] Problem section explains the "why" (2-3 paragraphs)
- [ ] Solution describes high-level approach
- [ ] Key technical decisions with rationale and trade-offs
- [ ] All changed files listed with specific changes
- [ ] Testing section with checkmarks and details
- [ ] Visual Evidence records READY with attached media or a warned local handoff, SKIPPED with a reason, or N/A with a reason
- [ ] Business impact connected to user/business value
- [ ] Concrete metrics (files, lines, tables)
- [ ] Breaking changes clearly marked or confirmed none
- [ ] Deployment notes documented
- [ ] Humanizer pass applied without changing technical facts
- [ ] Attribution is Dex-only; no Claude Code generated-by footer or Claude co-author text

## What Not to Do

- Vague descriptions ("Fixed some bugs", "Updated code")
- Missing context (not explaining WHY)
- No testing details ("Tests pass")
- No business impact
- Huge unfocused PRs doing too many unrelated things
- Claude attribution footers such as "Generated with Claude Code"
